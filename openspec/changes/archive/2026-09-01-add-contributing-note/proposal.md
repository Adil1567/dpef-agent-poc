## Why

There's no `CONTRIBUTING.md` explaining how to work with this repo's OpenSpec setup - a new contributor wouldn't know that changes go through `openspec new change`, get reviewed via PR, then archived after merge.

## What Changes

- Add a `CONTRIBUTING.md` at the repo root with a short guide to the OpenSpec workflow used here.

## Capabilities

### New Capabilities
- `contributing-guide`: a root-level guide explaining the OpenSpec change lifecycle used in this repo.

### Modified Capabilities
(none)

## Impact

- Affects: repo root (`CONTRIBUTING.md`) only.
